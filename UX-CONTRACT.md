# Customer workflow contract

[AGENTS.md](AGENTS.md) and the [implementation guide](docs/IMPLEMENTATION_BEST_PRACTICES.md) govern application development. Backend contracts are the sibling API's `storeAppConfiguration`, `storeLocation`, `locationProductListing`, `promotion`, `event`, `customerAccount`, and `customerLocationMembership` modules. Web transport models corroborate the wire format; owner/portal permissions do not apply to customers.

| Capability | Canonical owner | Behavior |
| --- | --- | --- |
| Launch | RootStartupService and StoreSessionService | Resolve optional existing auth, refresh public bootstrap, validate location, and apply theme before dismissing splash. Show recoverable configuration/failure states. |
| Target identity | BusinessConfig and target xcconfig | A dedicated target selects one business, public app key, logo, bundle, and environment URLs. Bootstrap and public location reads validate that tenant. Production requires configured HTTPS and never falls back to localhost. |
| Theme | UserDefaultsService and StoreThemeBuilder | Restore a validated tenant-specific definition before splash and reconstruct Rune Theme synchronously. Cache schema 2 resolves all supported radius roles; schema 1 migrates with existing defaults. Invalid or foreign definitions fall back to built-in styling. |
| Location navigation | NavigationService, MainViewModel, and StoreSessionService | Keep the store tab flow at the root. Restore a validated saved location or automatically select the sole location. Otherwise present a non-dismissible location sheet; Change Location presents it again. Missing age approval requires a location tap, including for a sole location. Keep the active store and saved choice while selecting; commit and persist the new location only after validation and any affirmation, then dismiss the sheet. |
| Location presentation | LocationsViewModel, StoreNavHeader, and LocationSelectionCard | Enrich bootstrap summaries through the existing public location endpoint. Show full addresses, today's local hours (including exceptions and split intervals), and server open/closed status. A failed details request preserves selection and offers retry. Location and age sheets share a safe-area-padded store identity header. |
| Age sheet | NavigationService, AgeVerificationScreen, AgeVerificationViewModel, and StoreSessionService | Only an explicit location selection can present the non-dismissible native age sheet, replacing the location picker. I agree records local policy evidence immediately, commits the selected location, and dismisses the sheet. The session owns authenticated acceptance recording in the background; guests remain local and separate. Bootstrap and identity/policy changes that require affirmation present the picker first. |
| Store tabs | TabBarNavigationService, StoreDetailsScreen, and TabBarScreen | JobLens's BubbleTabBarView selects Store overview, Menu, or Account above the root TabView with its native bar hidden. Each tab retains its own navigation stack and feature ViewModel, without an enclosing NavigationStack. Switching to a different location resets paths, presentations, and selected tab, and creates fresh feature ViewModels; opening the picker or reselecting the current location preserves them. The overlay stays mounted across selection changes, offsets out of view when hidden, and ignores keyboard safe-area changes. Shared content spacing keeps scrolling content and pinned authentication actions above the bar. |
| Search/filter | StoreShopViewModel and CatalogCategoryFilters | Search and parent/subcategory selections replace results, cancel superseded work, and reset pagination. The first category and its first subcategory are selected by default; changing the parent selects its first child. Neither rail includes All. Category images lead titles without an image background, and selected pills omit checkmarks. Horizontal pill rails expose category and child selections; the child rail reveals/replaces through a blur transition with value-scoped bouncy animation. Interactive requests show inline progress and keep controls usable. Search waits 300 milliseconds after the latest edit and cancels superseded debounce/request work. Clear is immediate; submit flushes a pending search or retries a failure without repeating an already submitted query. Search and category rails use compact theme spacing; no-results offers Clear filters. |
| Catalog paging/sort | StoreShopViewModel | Every sort uses server order before paging and explicit load-more with server metadata. Filter/search/sort changes cancel old requests and reset paging; load-more preserves the selected order. Menu uses Rune pull-to-refresh with custom progress and release feedback instead of a refresh button. Refresh reloads categories and products, preserving valid selections or falling back to the first available category/child; completion feedback follows the actual request outcome. |
| Favorites | UserDefaultsService, FavoriteProductsScreen, and FavoriteProductsViewModel | Local, tenant-specific product IDs; shared publisher keeps feed, details, and favorites consistent for guests and signed-in customers. Menu's filled heart pushes the location-scoped Favorite Products screen; Back and Browse products return to Menu. Favorites is not a tab. Adding or removing a favorite shows a Rune toast with the product title and the completed action. |
| Product presentation/media | Public API projections, Product, and shared product views; Rune ImageSource owns image loading | Cards and details share real available minimum display prices, image placeholders, and independent favorite actions. Active image media carries a backend-provided URL and is ordered by display order and stable ID. Cards, gallery pages, and thumbnails load that URL directly; no separate URL lookup or client MIME filtering occurs. Details retain stable selected media identity. Successful catalog/favorites refresh replaces product media and its URLs together. |
| Product details | ProductDetailsScreen, ProductDetailsViewModel, and existing product components | Keep the gallery's selectable thumbnails beneath its selected image, use the standard navigation Back/heart actions, and show every pricing variant in a horizontal rail. Render all supplied attributes through their existing display values. Recommended reads at most seven featured products from the current location/category, excludes the current product, and shows up to six with shared favorites and the existing product route. This optional request owns its task and cannot block product loading or present a product-load error. Maps opens the matching location's actual address and Call Store opens the public store phone through UIApplication; unavailable contact actions are disabled and failed opens use AlertService. Bundled transparent category URLs are shared with the catalog through ProductCategoryImageView. |
| Promotion actions | StoreOverviewViewModel, StorePromotionsCarousel, PromotionProductsScreen, and PromotionProductsViewModel | GENERAL is display-only, with no button or tap analytics. SALE and NEW_PRODUCT open one linked product directly or push the linked-product list for several. Summaries retain business products unavailable at the current location; selecting one explains the unavailability through AlertService. Available products use the supplied location listing ID for the existing product-details route. LINK opens a validated HTTPS URL in the external browser through UIApplication and reports invalid/failed opens through AlertService. Promotions do not alter product pricing. Source: API [promotion rules](../LeafLaunch-API/docs/UBIQUITOUS_BUSINESS_LOGIC.md#promotions-and-events). |
| Event details | StoreOverviewViewModel, StoreEventsViewModel, NavigationService, and EventDetailsViewModel | Every event card pushes details on the current Store navigation stack using its loaded public event and location context. Location-specific schedules override global dates, including an omitted local end date. Show the full description and address, directions, and the optional external website. Back restores the source overview or events list; opening details needs no new API request or modal. |
| Events paging | StoreEventsViewModel | Home requests ten events and View More pushes a location-scoped Events screen. Its existing public endpoint loads twenty items at a time with server paging metadata and duplicate-ID filtering. Reappearance refreshes the loaded range; refresh and paging retain visible data on failure, expose retry, and present errors through AlertService. Route context is installed before lifecycle work. |
| Store overview | StoreOverviewViewModel, StorePromotionsCarousel, StoreInfoView, and existing product cells | The location name and downward chevron in the header retain the original vertical spacing and open the existing picker without committing a selection; no separate location card remains. Promotions show a centered, filled image, title, and optional subtitle over a fading black caption that shrinks when the subtitle is absent. They advance every five seconds with easing, reset without an animated rewind, and pause during scrolling and inactive app phases; their view-scoped task cancels on disappearance. Centered page dots sit six points below, without arrows. Home hides the entire Promotions and Events sections when their lists are empty, without empty-state copy. Promotions, events, and featured products scroll horizontally with safe-area insets and full-width viewports. Distinct bundled images cover absent or failed promotion and event media. Event images fill and clip within the existing card width and a fixed 160-point height, including fallback assets. Event title/date spacing is four points. Featured Products reads six items from the existing public location-products endpoint with sort=featured and shared favorites. Compact section spacing leads into the white Store Info footer, showing actual address, expanded Monday–Sunday Store Hours, compact date-grouped special hours, and available phone/email links; hours omit the next-day annotation. There is no contact disclosure or full-menu action. |
| Account | AuthService and StoreAccountViewModel | Browsing stays available without registration. The trailing settings gear presents Settings through the active tab's NavigationService. Firebase auth bridges to actual CustomerAccount endpoints. Loyalty reads require an authenticated account and location membership. |
| Forms and Select/Listbox | Native SwiftUI controls and Rune | Native TextField, SecureField, Picker, and Link behavior. Rune `.asButton` covers ordinary custom actions; native buttons retain roles the modifier cannot express. Existing app components cover primary action styling. |
| Card surfaces | LLAppCardView and CommerceSurface | All app card composition that uses Rune AppCardView passes through LLAppCardView, with no shadow and Rune appBorder at 1.5 points in its default color. CommerceSurface supplies the large-radius padded variant. Settings rows and the version card also use the theme large radius. |
| Accessibility customization | Native SwiftUI and Rune behavior | App-owned components, views, and screens omit explicit accessibility modifiers and Reduce Motion environment handling. Native control behavior and Dynamic Type layout remain intact. |
| Loading/errors | Owning ViewModel and injected AlertService | Focused ViewModel helpers present errors directly; no `.errorHandler`. Async tasks show/dismiss their own unique Rune loading alert. Loading, empty, failure, and retry are explicit; cancellation cannot present an error or stale result. |
| Scrollbar and Date | Native SwiftUI/Foundation | Platform scrolling indicators and date controls; no custom browser scrollbar or date implementation. |

Approvals retain the requested `[userId: [state]]` shape with separate policy metadata; legacy entries lacking evidence deliberately re-attest. Identity, location, and configuration refreshes reevaluate approval. Canonical policy rules remain in the sibling API’s [business document](../LeafLaunch-API/docs/UBIQUITOUS_BUSINESS_LOGIC.md#legal-bootstrap-and-hours).

Store Info displays actual location details, opening hours, and safe public store contact information supplied by launch endpoints. The app key is a public identifier and never an authentication credential. Rune colors, fonts, media references, and supported radius roles share the canonical API branding definition. See [customer architecture](docs/CUSTOMER_ARCHITECTURE.md) for target configuration, contracts, and external provisioning values.

The shared storefront construction is documented in [DESIGN.md](DESIGN.md). Theme definitions remain store-owned; all presentation uses the environment Rune style. Account, product details, and catalog initial failures offer explicit retry without turning failures into successful empty states. Splash retains its immediate, exactly-once startup callback alongside its visual entrance.

Follow [repository verification rules](AGENTS.md#verify-and-maintain). Source inspection, Swift syntax parsing, focused Foundation model typechecking, plist validation, explicit target membership, and whitespace checks establish source consistency. Device/runtime behavior and push delivery require separately authorized validation.
