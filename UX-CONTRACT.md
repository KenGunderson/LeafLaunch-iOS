# Customer workflow contract

[AGENTS.md](AGENTS.md) and the [implementation guide](docs/IMPLEMENTATION_BEST_PRACTICES.md) govern application development. Backend contracts are the sibling API's `storeAppConfiguration`, `storeLocation`, `locationProductListing`, `promotion`, `event`, `customerAccount`, and `customerLocationMembership` modules. Web transport models corroborate the wire format; owner/portal permissions do not apply to customers.

| Capability | Canonical owner | Behavior |
| --- | --- | --- |
| Launch | RootStartupService and StoreSessionService | Resolve optional existing auth, refresh public bootstrap, validate location, and apply theme before dismissing splash. Show recoverable configuration/failure states. |
| Target identity | BusinessConfig and target xcconfig | A dedicated target selects one business, public app key, logo, bundle, and environment URLs. Bootstrap and public location reads validate that tenant. Production requires configured HTTPS and never falls back to localhost. |
| Theme | UserDefaultsService and StoreThemeBuilder | Restore a validated tenant-specific definition before splash and reconstruct Rune Theme synchronously. Cache schema 2 resolves all supported radius roles; schema 1 migrates with existing defaults. Invalid or foreign definitions fall back to built-in styling. |
| Location navigation | NavigationService, MainViewModel, and StoreSessionService | Keep the store tab flow at the root. Restore a validated saved location or automatically select the sole location. Otherwise present a non-dismissible location sheet; Change Location presents it again. Missing age approval requires a location tap, including for a sole location. Keep the active store and saved choice while selecting; commit and persist the new location only after validation and any affirmation, then dismiss the sheet. |
| Age sheet | NavigationService, AgeVerificationScreen, AgeVerificationViewModel, and StoreSessionService | Only an explicit location selection can present the non-dismissible native age sheet, replacing the location picker. I agree records local policy evidence immediately, commits the selected location, and dismisses the sheet. The session owns authenticated acceptance recording in the background; guests remain local and separate. Bootstrap and identity/policy changes that require affirmation present the picker first. |
| Store tabs | TabBarNavigationService, StoreDetailsScreen, and TabBarScreen | JobLens's BubbleTabBarView selects Store overview, Shop, Favorites, or Account above the root TabView with its native bar hidden. Each tab retains its own navigation stack and feature ViewModel, without an enclosing NavigationStack. Switching to a different location resets paths, presentations, and selected tab, and creates fresh feature ViewModels; opening the picker or reselecting the current location preserves them. The overlay stays mounted across selection changes, offsets out of view when hidden, and ignores keyboard safe-area changes. Shared content spacing keeps scrolling content and pinned authentication actions above the bar. |
| Search/filter | StoreShopViewModel and CatalogCategoryFilters | Search and parent/subcategory selections replace results, cancel superseded work, and reset pagination. Changing the parent clears its subcategory. Horizontal pill rails expose category and child selections; the child rail reveals/replaces through a blur transition with value-scoped bouncy animation. Interactive requests show inline progress and keep controls usable. Search offers clear and submit controls; no-results offers Clear filters. |
| Catalog paging/sort | StoreShopViewModel | Every sort uses server order before paging and explicit load-more with server metadata. Filter/search/sort changes cancel old requests and reset paging; load-more preserves the selected order. |
| Favorites | UserDefaultsService | Local, tenant-specific product IDs; shared publisher keeps feed, details, and favorites consistent for guests and signed-in customers. |
| Product presentation/media | Product and shared product views; screen ViewModels own signed URL work | Cards and details share real available minimum prices, truthful variant discounts, image placeholders, and independent favorite actions. Only active supported image media is shown, ordered by display order and stable ID. Details page and thumbnails share stable selected media identity. Shop/Favorites sign cover URLs through the existing endpoint with at most four in flight; cancellation and request ownership guard every result. Successful favorites refresh replaces cover URLs so changed media cannot retain a retired cover. |
| Account | AuthService and StoreAccountViewModel | Browsing stays available without registration. The trailing settings gear presents Settings through the active tab's NavigationService. Firebase auth bridges to actual CustomerAccount endpoints. Loyalty reads require an authenticated account and location membership. |
| Forms and Select/Listbox | Native SwiftUI controls and Rune | Native TextField, SecureField, Picker, and Link behavior. Rune `.asButton` covers ordinary custom actions; native buttons retain roles the modifier cannot express. Existing app components cover primary action styling. |
| Card surfaces | LLAppCardView and CommerceSurface | All app card composition that uses Rune AppCardView passes through LLAppCardView, with no shadow and Rune appBorder at 1.5 points in its default color. CommerceSurface supplies the large-radius padded variant. |
| Accessibility customization | Native SwiftUI and Rune behavior | App-owned components, views, and screens omit explicit accessibility modifiers and Reduce Motion environment handling. Native control behavior and Dynamic Type layout remain intact. |
| Loading/errors | Owning ViewModel and injected AlertService | Focused ViewModel helpers present errors directly; no `.errorHandler`. Async tasks show/dismiss their own unique Rune loading alert. Loading, empty, failure, and retry are explicit; cancellation cannot present an error or stale result. |
| Scrollbar and Date | Native SwiftUI/Foundation | Platform scrolling indicators and date controls; no custom browser scrollbar or date implementation. |

Approvals retain the requested `[userId: [state]]` shape with separate policy metadata; legacy entries lacking evidence deliberately re-attest. Identity, location, and configuration refreshes reevaluate approval. Canonical policy rules remain in the sibling API’s [business document](../LeafLaunch-API/docs/UBIQUITOUS_BUSINESS_LOGIC.md#legal-bootstrap-and-hours).

Store Info displays the safe business projection and actual location details supplied by public launch endpoints. The app key is a public identifier and never an authentication credential. Rune colors, fonts, media references, and supported radius roles share the canonical API branding definition. See [customer architecture](docs/CUSTOMER_ARCHITECTURE.md) for target configuration, contracts, and external provisioning values.

The shared storefront construction is documented in [DESIGN.md](DESIGN.md). Theme definitions remain store-owned; all presentation uses the environment Rune style. Account, product details, and catalog initial failures offer explicit retry without turning failures into successful empty states. Splash retains its immediate, exactly-once startup callback alongside its visual entrance.

Follow [repository verification rules](AGENTS.md#verify-and-maintain). Source inspection, Swift syntax parsing, focused Foundation model typechecking, plist validation, explicit target membership, and whitespace checks establish source consistency. Device/runtime behavior and push delivery require separately authorized validation.
