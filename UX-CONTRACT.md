# Customer workflow contract

[AGENTS.md](AGENTS.md) and the [implementation guide](docs/IMPLEMENTATION_BEST_PRACTICES.md) govern application development. Backend contracts are the sibling API's `storeAppConfiguration`, `storeLocation`, `locationProductListing`, `promotion`, `event`, `customerAccount`, and `customerLocationMembership` modules. Web transport models corroborate the wire format; owner/portal permissions do not apply to customers.

| Capability | Canonical owner | Behavior |
| --- | --- | --- |
| Launch | RootStartupService and StoreSessionService | Resolve optional existing auth, refresh public bootstrap, validate location, and apply theme before dismissing splash. Show recoverable configuration/failure states. |
| Target identity | BusinessConfig and target xcconfig | A dedicated target selects one business, public app key, logo, bundle, and environment URLs. Bootstrap and public location reads validate that tenant. Production requires configured HTTPS and never falls back to localhost. |
| Theme | UserDefaultsService and StoreThemeBuilder | Restore a validated tenant-specific definition before splash and reconstruct Rune Theme synchronously. Cache schema 2 resolves all supported radius roles; schema 1 migrates with existing defaults. Invalid or foreign definitions fall back to built-in styling. |
| Location navigation | NavigationService, MainViewModel, LocationListViewModel, and StoreSessionService | Keep the store tab flow at the root. Restore a validated saved location or automatically select the sole location. Without a committed active location, keep the location sheet non-dismissible. Change Location from an active store presents the same picker with a Close action and native swipe dismissal; cancelling discards the pending choice and restores the existing store/session without changing the persisted location or tab paths. Highlighting an uncommitted row does not enable dismissal. Dismissal eligibility belongs to StoreSessionService and is invalidated by bootstrap, identity changes, or mandatory age re-attestation; age verification remains non-dismissible. Tapping a store updates a pending selection; only Continue invokes the existing session validation and age flow, including for a sole location missing approval. Preselect the current store, or the sole store when no current choice exists. Preserve pending selection during filtering and request failures. Keep the active store and saved choice while selecting; commit and persist the new location only after validation and any affirmation, then dismiss the sheet. Prevent duplicate Continue requests while the session is loading. |
| Location presentation | LocationListScreen, LocationListViewModel, StoreNavHeader, LocationSelectionCard, LocationSearchControls, and LocationSelectionFooter | Enrich bootstrap summaries through the existing public location endpoint. Show city/region, street/postal address, and the server open/closed label; omit opening-hour ranges in the picker. A failed details request preserves selection and offers retry. The picker and age consent share the padded store identity header. The picker uses independent location cards with explicit selection indicators and a bottom safe-area Continue-only footer. |
| Location search | LocationListViewModel and LocationSearchLocator | Filter the finite bootstrap location list locally by store name, region, loaded address, and city; local clearing is immediate, and no matches offers Clear Search. A complete ZIP code in the field always determines the search center through Apple geocoding, including during refresh, and ranks all tenant locations by their geocoded addresses, nearest first, with unresolved addresses after resolved stores. A device coordinate never overrides an entered ZIP. ZIP edits debounce for 300 milliseconds and explicit submission runs immediately. When location access is already authorized and the field is untouched and empty, opening the picker makes one optional approximate-location lookup and prefills its ZIP when available without asking for permission. Use My Location may request when-in-use permission on explicit tap and performs the same ZIP-prefill lookup. The resulting ZIP uses the same ZIP-centered ranking as manual input; only when no supported ZIP can be resolved does the empty field fall back to device-coordinate ranking. Editing or clearing the field cancels pending autofill and prevents it from overwriting manual input or repopulating a deliberately cleared field. Optional automatic lookup failures stay quiet; explicit lookup failures use AlertService. Coordinates are not sent to the LeafLaunch API, logged, or persisted. Typing, clearing, continuing, or leaving the screen cancels location work. Authorized lookup/geocoding times out after twenty seconds; denial or failure uses the existing AlertService and leaves manual search available. |
| Age step | NavigationService, LocationListScreen, LocationListViewModel, LocationSelectionStep, and StoreSessionService | Only an explicit location selection can switch the existing non-dismissible location sheet to its ageVerification enum state. Content and bottom actions animate with blur replacement while the sheet identity remains stable. The age-specific confirmation action records local policy evidence immediately, commits the selected location, and dismisses the sheet. Back, Change, and Exit discard the pending candidate and return to the location picker without recording approval. Returning to selection reloads location details through the step-scoped task; leaving selection cancels enrichment and nearby searches so their late results or errors cannot appear over consent. The session owns authenticated acceptance recording in the background; guests remain local and separate. Bootstrap and identity/policy changes that require affirmation present the picker first. |
| Store tabs | TabBarNavigationService, StoreContainerScreen, and TabBarScreen | JobLens's BubbleTabBarView selects Store overview, Menu, or Account above the root TabView with its native bar hidden. Each tab retains its own navigation stack and feature ViewModel, without an enclosing NavigationStack. Switching to a different location resets paths, presentations, and selected tab, and creates fresh feature ViewModels; opening the picker or reselecting the current location preserves them. The overlay stays mounted across selection changes, offsets out of view when hidden, and ignores keyboard safe-area changes. Shared content spacing keeps scrolling content and pinned authentication actions above the bar. |
| Search/filter | ProductListViewModel, CatalogCategoryFilters, and CatalogCategoryTab | Search and parent/subcategory selections replace results, cancel superseded work, and reset pagination. Only real category/subcategory options appear in both rails and native Filters. The first category and its first child are selected by default; changing the parent selects its first child. A second visible rail exposes the selected category's children. Each row has one persistent underline overlay that follows the selected tab's unique geometry anchor, outside button press effects, through its own matched-geometry namespace. Tab taps and native Filters changes animate selection. Clear filters clears search and restores the first category/child while retaining sort. Interactive requests show inline progress and keep controls usable. Search waits 300 milliseconds after the latest edit and cancels superseded debounce/request work. Clear is immediate; submit flushes a pending search or retries a failure without repeating an already submitted query. Search and category rails use compact theme spacing; no-results offers Clear filters. |
| Catalog paging/sort | ProductListViewModel | Every sort uses server order before paging and explicit load-more with server metadata. Filter/search/sort changes cancel old requests and reset paging; load-more preserves the selected order. Menu uses Rune pull-to-refresh with custom progress and release feedback instead of a refresh button. Refresh reloads categories and products, preserving valid selections or falling back to the first real category/child when a selection disappears; completion feedback follows the actual request outcome. |
| Favorites | UserDefaultsService, FavoriteProductListScreen, and FavoriteProductListViewModel | Local, tenant-specific product IDs; shared publisher keeps feed, details, and favorites consistent for guests and signed-in customers. Menu's outlined heart and Account's Saved Products link push the location-scoped Favorite Products screen on their own stacks; Back returns to the source screen. Browse products returns to the root Menu catalog and selects that tab. Favorites is not a tab. Adding or removing a favorite shows a Rune toast with the product title and the completed action. |
| Product presentation/media | Public API projections, Product, and shared product views; Rune ImageSource owns image loading | Cards and details share real available minimum display prices, image placeholders, and independent favorite actions. Active image media carries a backend-provided URL and is ordered by display order and stable ID. Cards, gallery pages, and thumbnails load that URL directly; no separate URL lookup or client MIME filtering occurs. Details retain stable selected media identity. Successful catalog/favorites refresh replaces product media and its URLs together. |
| Product details | ProductDetailsScreen, ProductDetailsViewModel, and existing product components | Keep the gallery's selectable thumbnails beneath its selected image, use the standard navigation Back/heart actions, and show every pricing variant in a horizontal rail. Render all supplied attributes through their existing display values. Recommended reads at most seven featured products from the current location/category, excludes the current product, and shows up to six with shared favorites and the existing product route. This optional request owns its task and cannot block product loading or present a product-load error. Map opens the matching location's actual address, Call opens the public store phone, and Email opens the public support email through UIApplication; unavailable contact actions are disabled and failed opens use AlertService. Bundled transparent category URLs are shared with the catalog through ProductCategoryImageView. |
| Promotion actions | StoreDetailsViewModel, StorePromotionsCarousel, PromotionProductListScreen, and PromotionProductListViewModel | GENERAL is display-only, with no button or tap analytics. SALE and NEW_PRODUCT open one linked product directly or push the linked-product list for several. Summaries retain business products unavailable at the current location; selecting one explains the unavailability through AlertService. Available products use the supplied location listing ID for the existing product-details route. LINK opens a validated HTTPS URL in the external browser through UIApplication and reports invalid/failed opens through AlertService. Promotions do not alter product pricing. Source: API [promotion rules](../LeafLaunch-API/docs/UBIQUITOUS_BUSINESS_LOGIC.md#promotions-and-events). |
| Event details | StoreDetailsViewModel, EventListViewModel, NavigationService, and EventDetailsViewModel | Every event card pushes details on the current Store navigation stack using its loaded public event and location context. Location-specific schedules override global dates, including an omitted local end date. Show the full description and address, directions, and the optional external website. Back restores the source overview or events list; opening details needs no new API request or modal. |
| Events paging | EventListViewModel | Home requests ten events and View More pushes a location-scoped Events screen. Its existing public endpoint loads twenty items at a time with server paging metadata and duplicate-ID filtering. Reappearance refreshes the loaded range; refresh and paging retain visible data on failure, expose retry, and present errors through AlertService. Route context is installed before lifecycle work. |
| Store overview | StoreDetailsViewModel, StorePromotionsCarousel, StoreInfoView, and existing product cells | The header location action opens the existing picker without committing a selection; a separate status row uses the server open/closed state and daily hours. Promotions contain real copy with no image and expose their existing routes through View offer; GENERAL stays display-only. They advance every five seconds with easing, reset without an animated rewind, and pause during scrolling and inactive app phases; their view-scoped task cancels on disappearance. Centered page dots sit six points below, without arrows. Home hides the entire Promotions and Events sections when their lists are empty. All three rails retain full-width scrolling with safe-area insets. Events keep real local date/time/location captions, clipped media/fallbacks, and the existing details route; See all opens the paginated Events screen. Featured products reads six server-featured items, retains shared favorites, and offers View menu through the existing Menu tab. Store Info inherits the themed page canvas and displays the actual address, filled Map/Call/Email links, expanded Monday–Sunday hours with a server-local Today highlight, a native holiday-hours disclosure containing every upcoming exception/interval/reason, and available public phone/email links. Hours omit the next-day annotation. Visual composition and standard section spacing are owned by [DESIGN.md](DESIGN.md). |
| Account | AuthService, StoreSessionService, and AccountDetailsViewModel | Browsing stays available without registration. The trailing settings gear presents Settings through the active tab's NavigationService. Firebase auth bridges to actual CustomerAccount endpoints. The membership pass reads business-wide identity, status, balance, and join date from CustomerAccount, independent of location enrollment; View Membership opens a read-only native sheet with those values and the current location activity status. Location activity enrollment retains its explicit action. The recent activity preview shows the first server-ordered entry; View All pushes the location-scoped Points Activity route on the Account stack. Account does not expand or page its preview. Ledger reads still require an authenticated account and location membership. Saved Products pushes the existing location-scoped favorites screen on the Account stack; Your Store opens the existing location picker through StoreSessionService. Preserve loading, failure/retry, guest, identity-change cleanup, and sign-out behavior. |
| Points activity | LoyaltyHistoryListScreen, LoyaltyHistoryListViewModel, NavigationService, and StoreAccountHistoryRow | Install location context before tracking/loading. Fetch the existing authenticated loyalty endpoint in server order with explicit Load More and duplicate-ID filtering. Reappearance refreshes the loaded range; failures retain loaded entries and retry the failed refresh/page. Initial failures stay distinct from an empty ledger. Cancel owned tasks on teardown; request identity and authenticated-user checks prevent stale results/errors. Identity changes clear activity and return to the Account root. Back restores Account. Both app targets, live/mock factories, preview resolution, and customer_points_activity analytics remain wired. |
| Forms and Select/Listbox | Native SwiftUI controls and Rune | Native TextField, SecureField, Picker, and Link behavior. Rune `.asButton` covers ordinary custom actions; native buttons retain roles the modifier cannot express. Existing app components cover primary action styling. |
| Card surfaces | LLAppCardView and CommerceSurface | All app card composition that uses Rune AppCardView passes through LLAppCardView, with no shadow and Rune appBorder at 0.8 points in its default color. CommerceSurface supplies the large-radius padded variant. Settings rows and the version card also use the theme large radius. |
| Horizontal separators and flexible layout | LLDivider and native SwiftUI frames | Horizontal separators use the active quaternary background at 1.25 points. Content uses infinity frames with contextual alignment instead of Spacer views. |
| Accessibility customization | Native SwiftUI and Rune behavior | App-owned components, views, and screens omit explicit accessibility modifiers and Reduce Motion environment handling. Native control behavior and Dynamic Type layout remain intact. |
| Loading/errors | Owning ViewModel and injected AlertService | Focused ViewModel helpers present errors directly; no `.errorHandler`. Async tasks show/dismiss their own unique Rune loading alert. Loading, empty, failure, and retry are explicit; cancellation cannot present an error or stale result. |
| Scrollbar and Date | Native SwiftUI/Foundation | Platform scrolling indicators and date controls; no custom browser scrollbar or date implementation. |

Approvals retain the requested `[userId: [state]]` shape with separate policy metadata; legacy entries lacking evidence deliberately re-attest. Identity, location, and configuration refreshes reevaluate approval. Canonical policy rules remain in the sibling API’s [business document](../LeafLaunch-API/docs/UBIQUITOUS_BUSINESS_LOGIC.md#legal-bootstrap-and-hours).

Store Info displays actual location details, opening hours, and safe public store contact information supplied by launch endpoints. The app key is a public identifier and never an authentication credential. Rune colors, fonts, media references, and supported radius roles share the canonical API branding definition. See [customer architecture](docs/CUSTOMER_ARCHITECTURE.md) for target configuration, contracts, and external provisioning values.

The shared storefront construction is documented in [DESIGN.md](DESIGN.md). Theme definitions remain store-owned; all presentation uses the environment Rune style. Account, product details, and catalog initial failures offer explicit retry without turning failures into successful empty states. Splash retains its immediate, exactly-once startup callback alongside its visual entrance.

Follow [repository verification rules](AGENTS.md#verify-and-maintain). Source inspection, Swift syntax parsing, focused Foundation model typechecking, plist validation, explicit target membership, and whitespace checks establish source consistency. Device/runtime behavior and push delivery require separately authorized validation.
