# AGENTS.md

LeafLaunch is a SwiftUI iOS app built with Swift 6, FactoryKit, and Rune. This file is a task index: follow the links for the area you are changing instead of reading the whole repository. Browse the [documentation index](docs/README.md) for guides, examples, references, and setup instructions.

## Standing rules

- Do not run Xcode builds or tests unless the user explicitly asks. Do not write tests. Do not create a worktree, stage, commit, or push unless explicitly asked.
- Never over-architect. Make the smallest complete change using existing patterns and best practices; do not add speculative layers, protocols, generic frameworks, wrappers, or unrelated refactors. Add an abstraction only for a concrete current responsibility or demonstrated reuse.
- Split independent models into separate Swift files whenever possible; place them near the feature or service that owns them. Keep locally scoped nested types at the top of their existing owner, above properties.
- Preserve existing architecture, user changes, service contracts, navigation behavior, and async behavior. Search for an existing model, component, service, or helper before creating another.
- Follow the closest same-layer implementation and the applicable [implementation guide](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md) sections, which incorporate the Skillet semantic-linter references. Use LeafLaunch's actual names and contracts; preserve documented lifecycle exceptions. Style cleanup must preserve behavior; repository-wide formatting requires explicit scope.
- Follow the [core Swift conventions](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#core-swift-conventions) across all Swift layers: `self.` for instance properties and callable Factory properties, normally no `self.` for methods, and separated `SCREAMING_SNAKE_CASE` logger names. Calls with two or more arguments expand below `(`; `ForEach`, simple `min`/`max`, all padding calls, and frames containing `maxWidth:`/`maxHeight:` stay inline. Declarations with more than two parameters align under the first and keep `)`, effects, return type, and `{` on the final parameter line.
- Match the worked example's spacious bodies, the [switch layout](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#switch-layout), and explicit guard/`MainActor.run` interior spacing. Name complex expressions and long logical chains while preserving evaluation order and short-circuit behavior. Keep consecutive properties with the same wrapper together, with blank lines between wrapper groups.
- Keep screens and view models together by feature. Follow the [screen and ViewModel contract](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#screens-and-viewmodels): canonical screen member order, one `@StateObject` owner, weak navigation, route context before lifecycle work, first-appearance tracking before idempotent subscriber binding, and no screen subscriptions in `init`.
- Small, named `@ContentBuilder` helpers are a hard rule: keep `content()` as section/action composition, put collections in section helpers, and put rows/cards in their own helpers. Prefer private methods and existing components; see [readable SwiftUI composition](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#readable-swiftui-composition).
- Trigger fetch-backed screen loading and reappearance refresh with `.task { [weak viewModel] in viewModel?.loadData(showHud: self.viewModel.isFirstLoad) }`; keep initial fetches out of first-appearance callbacks. Every `loadData(showHud:)` ViewModel exposes read-only `isFirstLoad`; default `showHud` to `false`, clear first-load state only on successful uncancelled work, and retain existing reload timing. See the [lifecycle contract](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#lifecycle-and-analytics).
- Follow the [async ownership rules](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#async-tasks-loading-and-cancellation): name and cancel owned tasks, snapshot dependencies/context, check cancellation before results or errors, preserve main-actor UI mutation, and keep loading/empty state coherent.
- Use the [loading and alert example](docs/examples/VIEW_MODEL_LOADING_AND_ALERTS.md) for `loadData(showHud:)`: centralized `Constants.Message` copy, ViewModel-owned presentation, exact task-owned loader dismissal, and cancellation-safe cleanup. Preserve documented single-flight and identity guards.
- Reuse LeafLaunch components and Rune before custom UI. Centralize repeated Rune overrides in a focused app component or modifier with a small API, and migrate matching callers. Use the active environment style, semantic tokens, and established image/presentation APIs; add a focused app wrapper only for a real product-specific need or repeated treatment. See [Rune and app-owned UI](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#rune-and-app-owned-ui).
- Follow [global UI conventions](docs/reference/GLOBAL_UI_CONVENTIONS.md): open `LLSection` groups, semantic `LLSpacing` roles, `runeAsButton` for app actions, and shared segmented-content transitions. Preserve commerce surfaces, button/card geometry, native system roles, focus, and editor state.
- Every `VStack`, `HStack`, and lazy stack declares explicit style-resolved spacing, including previews. Prefer matching `LLSpacing` roles, then the correct design-token family; unmatched values use that family's `.custom(...)`. Use `runePadding` and `runeCornerRadius` for view padding and radii. Keep numeric scale definitions in their existing runtime owners.
- Retain resolved empty states and content during same-context refresh. Initial unresolved requests/permissions stay neutral until resolution. Suitable read-only fetch-backed screens pass async `onRefresh:` to `LLAppHeaderScrollView` and await actual ViewModel work with no routine HUD; preserve Menu's specialized refresh feedback.
- In async catches, check current-task cancellation before logging, wrapping, retrying, failure rollback, or presentation. Propagate qualified `APIError.cancelled` for typed API throws, `CancellationError()` for other throwing work, or return from nonthrowing owners. Preserve exact task-owned cleanup and stronger request/context guards.
- Present errors in the owning ViewModel through its injected RNAlertService; never use `.runeErrorHandler`. Follow the focused error helpers and individually owned loading alerts in the [async rules](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#async-tasks-loading-and-cancellation).
- When adding or changing dependencies or features, keep protocols, live and mock registrations, preview/mock resolver entries, route destinations/context, analytics, and applicable API endpoints/fixtures in [integration parity](docs/guides/IMPLEMENTATION_BEST_PRACTICES.md#feature-integration-parity). Match constructor signatures and actor annotations.
- New Swift files must be added to the appropriate target in [project.pbxproj](LeafLaunch.xcodeproj/project.pbxproj); this project uses explicit file references.
